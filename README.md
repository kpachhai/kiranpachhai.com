# kiranpachhai.com

Static personal site built with Astro 7 and TypeScript. Fonts are self-hosted woff2 subsets (see `public/fonts/LICENSES.md`).

- `npm run dev` starts the dev server
- `npm run build` writes the site to `dist/`
- `npm test` runs the unit tests with vitest
- `npm run test:e2e` runs Playwright tests
- `public/CNAME` carries the custom domain for static hosting

## Maintenance

- **Quality gates.** `npm run gates` runs eight gates in order, each as its own process: unit tests (which build `dist/` once), typecheck, provenance, copy scan, budget, axe, link check and Lighthouse (mobile, median of 3 runs). When all eight pass it writes `src/data/gates.json`, which the footer shows as "Passed 8 of 8 gates on <date>", then rebuilds `dist/` once and checks that the built footer carries that line; any failure exits non-zero and leaves that file as it was. Each gate also runs alone: `npm run gate:budget`, `gate:a11y`, `gate:links`, `gate:lighthouse`, `gate:copy`, `gate:provenance`. Lighthouse uses Playwright's Chromium unless `CHROME_PATH` names another browser. The link check skips linkedin.com, twitter.com, x.com and youtube.com, which block automated clients.
- **npm overrides.** `fflate` is pinned to 0.7.5 because satori depends on an older range with a known advisory; drop the override once satori depends on fflate 0.7.5 or later. `basic-ftp` (under `@lhci/cli`) and `glob` (under `linkinator`) are pinned past their advisories for the same reason; drop each once its parent depends on a fixed release. `npm audit` should report 0 vulnerabilities.
- **Fonts.** The mono stack puts local fallback faces (Menlo, DejaVu Sans Mono, Liberation Mono; Consolas in its own face) right after Martian Mono, scaled to its metrics with `size-adjust` and ascent/descent overrides, so the swap to the web font does not shift layout. `tests/unit/fonts.test.ts` checks those values against the font file. The Newsreader italic is loaded with `font-display: optional`: when it is not ready for first paint, that visit shows the fallback italic and the layout never shifts. The trade-off is that a first visit on a slow connection may not show the real italic. The other faces use `swap`.
- **CI.** `.github/workflows/ci.yml` runs on every pull request and every push to `main`, with a read-only token, and never deploys. The `verify` job (Ubuntu) runs `npm ci`, `npm run data`, the Playwright browsers install, `npm run build`, `npm run gates` and `npm run test:e2e`, and uploads `dist` and the Playwright report as artifacts. The `windows-smoke` job builds on Windows and runs the `@windows` Playwright test (fonts load, CLS under 0.02 on `/`), the one place the Consolas fallback face is exercised. Superseded runs on the same ref are cancelled.
- **Deploy.** To publish, open the repository's Actions tab, choose "Deploy" and run the workflow manually (`workflow_dispatch`); it never runs from a push or a schedule until the owner turns that on. The `verify` job repeats the CI checks; the `publish` job (the only one with `contents: write`) downloads the verified `dist`, asserts `dist/CNAME` is `kiranpachhai.com`, tags the current `gh-pages` head `pre-redesign-2026` if that tag is absent on origin, then replaces the `gh-pages` branch root with `dist` in one commit titled "Deploy <short sha>". The workflow does nothing when dispatched from a branch other than `main`. The built `dist` artifact is kept for one day, so rerun the whole workflow (not only the publish job) after that. Pages must serve from the `gh-pages` branch root. Every action is pinned to a commit SHA; Dependabot proposes weekly updates for npm and actions.
- **Rollback.** Rollback is an owner action on the `gh-pages` branch, and Pages rebuilds from it; afterwards confirm the custom domain and HTTPS still serve. To restore the pre-redesign site, push the tag the first deploy made (a lightweight tag on the old `gh-pages` head): `git push --force origin refs/tags/pre-redesign-2026:refs/heads/gh-pages`. To undo one deploy, find the earlier "Deploy <short sha>" commit with `git log --oneline origin/gh-pages` and push it: `git push --force origin <commit>:refs/heads/gh-pages`. The next Deploy run replaces the branch root again.
- **GitHub data refresh.** `npm run data` with `GH_TOKEN` (or `GITHUB_TOKEN`) set writes `src/data/github.json`, which is gitignored and preferred by the build; CI and Deploy run it on every build. The committed `src/data/github.snapshot.json` is the fallback when there is no token or GitHub cannot be reached, and it is refreshed by hand only when the owner asks: run `npm run data`, copy `src/data/github.json` over `src/data/github.snapshot.json`, run `npm test`, and commit the snapshot. A repo shows in the Upstream ledger, the proof drawer and the no-JS area list only once it is in `src/data/upstream-map.ts` and the data has a status for it.
- **Where content lives.** Every claim is in the typed content model under `src/model/data/` (areas and proofs in `domains.ts`, case studies, talks, roles, skills, materials, methods, modes and the timeline), each with a source. Upstream repos, their neutral labels and their pinned links are in `src/data/upstream-map.ts`. `npm run gates` writes `src/data/gates.json`, which the footer reads, so commit it with the change it certifies.
